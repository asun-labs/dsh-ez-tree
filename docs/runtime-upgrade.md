# 可选独立桌面运行时兼容

0.1.2 的日常技能流程直接加载随插件交付的编辑页，不依赖独立程序。以下维护机制保留给旧版安装及外部 MCP；不再提供常驻管理入口。

`dsh-ez-tree` 0.1.2 沿用原应用 ID `com.asun-labs.ez-tree`、Cordis entry、RPC、账号摘要、项目与导出目录。插件包由 `@asun-labs/dsh-ez-tree` 统一为 `dsh-ez-tree`，不会据包名创建第二套用户数据。

运行时升级使用随插件固定的目标发布清单；历史 0.1.0、0.1.1 的原始清单保存在 `releases/legacy/`。只有文件摘要和内部应用身份均匹配固定清单的旧版，才会被识别为可用安装。未校验目录、被修改的程序和任意其他版本不会作为兼容回退执行。

当已安装 0.1.0 而目标为 0.1.2 时，状态返回：

```json
{
  "installed": true,
  "version": "0.1.0",
  "targetVersion": "0.1.2",
  "updateAvailable": true
}
```

维护 RPC 仍识别已安装的旧版；兼容启动和准备 MCP 使用已验证的旧版路径。升级前须关闭当前账号由插件启动的编辑器。其他账号的实例和用户另行启动的进程不由此操作强制终止。

升级把目标版本安装到同一账号的独立版本目录，完成下载摘要、逐文件及应用身份校验后才发布安装。失败时旧版继续可用；如果目标版本损坏，而旧版仍通过其固定清单校验，则仍可打开旧版并重新升级。

升级成功后，新的打开操作和新生成的 MCP 配置指向 0.1.2。原 0.1.0 程序目录保留，使已保存的旧 MCP 配置继续可用。项目、导出、技能引用和连接器 ID 不移动、不重命名。要让既有连接器改用新版，可按 docs/mcp.md 更新独立 MCP 启动配置；已有配置不会因安装新版而被静默改写。

卸载需要先关闭当前账号由插件启动的任一受管理版本编辑器。卸载只删除已识别的 0.1.0、0.1.1 和当前版本程序目录，保留项目、导出及其他用户数据，也不删除未知版本目录。卸载后，指向这些程序的 MCP 配置需重新安装应用后再使用。

回归测试使用真实 ZIP 与固定 SHA-256 清单验证旧版识别、旧版启动身份、成功升级、失败回退、程序篡改拒绝、旧 MCP 路径保留和保留项目的卸载。
